## 0. 一句话

**三轮下来，唯一被证实有效的手段是"提高输入分辨率"（960→1280），且已被 FP16 把速度代价抵消；而"少数类过采样"这条路被证伪。真正的瓶颈不在分辨率，也不在样本数量，而在数据分布与真实缺陷形态覆盖。**

## 3. 已被证据支持的结论

1. **分辨率是有效变量**（Round 2，单变量对照，三条判据全过）。
2. **FP16 能抵消 1280 的速度代价**：101.4 → 164.9 FPS（+63%），精度 0.1020 → 0.1023。
3. **copy-paste 类过采样对稀有类无效，且有害**（B-1）：复制的是"已检出的外观"，漏检样本外观不同，过采样只放大误报。
4. **类 13 漏检：标注质量 + 类内形态覆盖不足 两层原因叠加**（逐实例 + 全数据集分析）：
   - **标注质量确有疑点**：16 条极端标注中至少 2 条疑似把**叶根/机舱连接区**误标为结构损伤（5.5M px² 占画面 27.9%；664k px² 一条）
   - **类内形态偏移**：漏检长宽比中位 1.67 vs 类 13 自身 1.25；>2 占 36.8% vs 13.8%
   - **但"长条形"并非数据集缺口**：全数据集多数类 26–50% 的实例是长条形（类 13 反而只有 13.8%）
   - 11/19 漏检图上模型零输出
   - **已排除**：与其它类标注重叠（0）、光照/对比度
   - ⚠️ **未定性**：类别定义是否需调整，需企业工程师确认

## 4. 已被排除的方向

| 方向 | 排除依据 |
|---|---|
| 高分辨率继续上调（>1280） | 1280 已把速度吃紧，收益递减未验证；且精度仍低于封存基线 |
| 少数类 copy-paste 过采样 | B-1 判否 |
| 全类 copy_paste 增强 | 会污染变量，且 B-1 已证方向无效 |
| 依赖 TensorRT 提速 | 当前 torch 2.9 与 TRT 库不兼容（pybind11 nullptr），FP16 已够 |
| 靠"训练更久"解决类 13 | 无证据支持：瓶颈是形态覆盖，不是收敛不足 |

## 6. 下一阶段方向（不急于开实验，先出方案）

按负责人指示，**暂不追加算力**（3b-1 100 轮、3b-2 200 轮均暂缓），先做数据分析与针对性优化，形成方案后再汇报。

建议聚焦四类问题：

| 方向 | 现有证据 | 可探索（960 分辨率下） |
|---|---|---|
| **数据分布 / 形态覆盖** | 类 13 细长型样本仅 12 个；漏检多为大面积极端形态 | 分层采样、按形态配额过采样（真实样本）、长尾重加权、极端标注复核 |
| **真实缺陷形态覆盖** | copy-paste 无效说明"合成不解决问题" | 定向补标真实样本；按形态建"覆盖度指标"而非只看类别计数 |
| **小目标漏检** | Round 1 主矛盾是漏检 | 大分辨率切片推理（SAHI 类）、特征金字塔/注意力、损失函数（如 WIoU、Focal）在 960 下的效果 |
| **定位质量** | 类 13 填充率/长宽比偏移，`mislocalized` 在部分类占比高 | 分割头改进、边界监督；用 IoU 分布而非单一 mAP 作为优化目标 |

**原则**：每个方向先给出"用现有数据即可验证的小实验设计"，再评估是否值得开机；避免再次出现"大批量训练但结论不可归因"。
