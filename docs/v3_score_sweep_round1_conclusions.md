# v3 score sweep Round 1 完整结论（2026-10-09）

> 依据：四组实验 manifest/results/metrics + 全量 val 预测导出（7,244 图 × 6 模型，含两封存基线）+
> 逐 GT 实例错误分解（polygon IoU≥0.5 匹配，conf=0.25）+ 双人复核（含第二方两轮意见）。
> 全程 test 锁定（test_used=false）。分析口径近似值，非官方 AP；官方指标以 metrics.json 为准。

## 0. 负责人必答题：模型是"看不见、分错类、还是框不准"？

**答：压倒性瓶颈是漏检（定义见下表注），其次是定位不准，分类错误占比最小但集中在特定类族。**

全量 val 7,413 个 GT 实例的错误分解（占 GT 比例）：

| 模型 | 漏检（无匹配） | 定位偏差(0.5≤IoU<0.75) | 分错类 | ok(IoU≥0.75) | 误报 FP |
|---|---|---|---|---|---|
| SEG 基线 | 73.5% | 13.8% | 5.2% | 7.5% | 1512 |
| exp1 SEG 960 | 68.3% | 17.1% | 6.5% | 8.1% | 2431 |
| exp2 SEG 1280 | **65.7%** | 17.4% | 7.1% | **9.8%** | 2291 |
| OBB 基线 | 71.6% | 18.2% | 5.4% | 4.9% | 1959 |
| exp3 OBB 960 | 68.3% | 20.9% | 6.2% | 4.6% | 2679 |
| exp4 OBB 1280 | 68.9% | 19.9% | 6.2% | 5.0% | **3835** |

> 口径说明：上表"漏检"指 GT 实例在 conf=0.25 下没有任何 polygon IoU≥0.5 的匹配预测（未达匹配阈值）。其中一部分实例仍存在低置信度（conf<0.25）或低重叠（IoU<0.5）的预测响应，**并非字面意义的"模型完全看不见/无任何反应"**；三档桶（漏检/定位偏差/ok）按最佳匹配 IoU 互斥划分。

**结论：该数据集的硬伤是检出（recall 层面），不是分类。** 即便最好的组合也有 ~2/3 的 GT 实例未达匹配阈值。
任何"换参数提分"若不针对漏检，天花板都很低。

## 1. 瓶颈排序（本轮证据）

1. **检出不足（漏检，口径见 §0 表注）**：全类平均漏检 66–74%；复核重灾区类 8/9/14 漏检 78–91%。2000 万像素图上小/细长目标在 960 输入下信息不足是主因之一。
2. **定位质量（框不准）**：0.5–0.75 IoU 区间的"半对"实例占 14–21%；OBB 侧更突出（基线即 18.2%）。这是 mAP50 与 mAP50-95 显著分离的来源（见 §3）。
3. **少数类样本不足**：维修痕迹 val 66 实例（train 占比同样低）、结构损伤 val 25 实例/22 图。单类 AP 波动 ±0.05 是常态（bootstrap CI 跨零），指标层面几乎不可判决。
4. **类别混淆（分错类）**：总量小（5–7%）但高度集中于**腐蚀族互混**（类 1/2/3/6 互判）与**裂纹族互混**（胶衣裂纹↔后缘弦向裂纹↔玻纤裂纹）、**附件族**（11↔12）。属标注边界/视觉相似性问题，非训练参数问题。
5. **OBB 定位**：OBB ok 率只有 SEG 一半（~5% vs ~8-10%），旋转框在细长目标上的 IoU 天然吃亏；exp4 的 FP 翻倍（3835）说明 1280-OBB 路线"多检但虚"。

## 2. 两个异常类的专题结论

### 维修痕迹（类 10，val 66 实例）
- 错误结构（基线→exp2 SEG）：漏检 50→50、误分 3→7、ok 7→2。exp2 在该类上确实略退（原始计数层面），但 **±3 个实例即可翻转结论**（bootstrap 95%CI [-0.242,+0.061] 跨零）
- 双人复核一致结论：**"小样本波动可解释但未证实"**；该类同时存在与表面油污的轻度互混（外观相近）
- 处置建议：转入标注质量排查（66 样本逐张人工）+ 下轮实验的定向增强对象

### 结构损伤（类 13，val 25 实例/22 图）
- 各模型原始计数几乎相同（漏检 20–22、ok 0–2），但 AP50-95 从基线 0.150 → exp3 0.113（-0.036）——**纯置信度排序波动**，非检出能力变化
- SEG 侧该类反而正向（+0.004/+0.024）：同一批图片同一套标签、任务头不同 → 指向**"结构损伤 vs 玻纤损伤/叶片开裂"边界在旋转框标注下更敏感**的疑点（第二方复核：疑点存在，未独立坐实）
- 处置建议：22 张图人工逐张核对标注（< 1 人时），再决定是否为类别定义问题

## 3. 1280 信号：成立一半，且**不能归因于分辨率**

### 事实
- SEG 侧：exp2 复核类 8/9/14 全正（+0.003/+0.010/+0.022），mAP50(M) 0.2570>0.2532、recall(M) 0.3352>0.3286 超基线，漏检率全场最低（65.7%）
- OBB 侧：**不成立**（mAP50 0.3512<0.3563、recall 0.4089<0.4157；FP 翻倍）

### 归因混淆声明（重要）
exp1→exp2 同时变更了 **6 个变量**，分辨率只是其一：

| 变量 | exp1 (960) | exp2 (1280) |
|---|---|---|
| imgsz | 960 | 1280 |
| epochs | 30 | 25 |
| batch | 8 | 4 |
| patience | 10 | 8 |
| lr0 | 5e-4 | 3e-4 |
| 增强 | mosaic 1.0, close_mosaic 10 | mosaic 0.7, copy_paste 0.15, scale 0.6, close_mosaic 5 |

**本轮证据只能支持"1280+低 lr+该增强组合在 SEG 侧对小类有正向信号"，不能单独归功于分辨率。**（OBB 侧同组合不成立。）
下一轮若要在报告里写"分辨率有效"，必须先做隔离实验（见提案文档方案 A）。

## 4. 训练吞吐遥测整理（替代 workers benchmark）

| 场景 | 吞吐 | 备注 |
|---|---|---|
| 8C 单卡, workers=4 | 1.0 it/s | CPU 解码瓶颈（单张 278ms，mosaic×4） |
| 8C 单卡, workers=8 | 1.57 it/s | CPU 饱和（commit 9eafa77） |
| 16C 单任务 | ~5 it/s | GPU0 独占 |
| 16C 双任务并行 | 各 ~4.5–5.5 it/s | CPU 平分后仍优于单任务独占的一半 |
| 1280 输入 | epoch 时长 ≈ 960 的 1.8–2 倍 | 8451 iter(batch4) vs 4226 iter(batch8) |

结论：纯 CPU 解码瓶颈；workers 8→12/16 的边际收益待下次正式训练顺便做受控对比（不单独开机）。
原始记录：`results/v3_score_sweep/benchmark_8c_*.log`、`stage1_monitor.log`。

> 配置口径（负责人评审意见 2026-10-10）：两份封存基线 YAML 保持 `workers: 4` 原样不改（与基线训练时实际配置一致，保证历史可复现）；workers=8 仅作为运行参数经 CLI `--workers 8` 覆盖生效（机制见 `docs/input_pipeline_audit.md`），或写入后续新实验配置，不回写封存基线。
